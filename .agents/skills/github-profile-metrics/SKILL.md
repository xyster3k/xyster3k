# Страница GitHub с учётом приватных проектов

Создай страницу, где посетитель видит сферу работы автора и обновляемые показатели, а сведения о приватных проектах остаются внутри процесса сбора. Основа механики проверена на `xyster3k/xyster3k` 2026-11-05.

## Материалы

- Прочитай [подробное руководство](references/guide.ru.md) перед реализацией. Оно описывает установку, источники чисел, доступы, архивы, динамику и диагностику.
- [assets/generate_private_metrics.py](assets/generate_private_metrics.py) содержит точную копию проверенного генератора. Его особенности описаны в руководстве.
- [assets/private-metrics.yml](assets/private-metrics.yml) содержит переносимый сценарий GitHub Actions с проверкой перед публикацией.
- [assets/validate_public_metrics.py](assets/validate_public_metrics.py) проверяет структуру публичных данных и отклоняет служебную заглушку, резервный источник коммитов и неполный поиск коммитов.

## Рабочий порядок

1. Найди целевой аккаунт и репозиторий, прочитай действующие инструкции, README, сценарии Actions и историю изменений. Сверь опубликованные JSON и SVG с последними запусками. Получай значения секретов только при необходимости; для обычной проверки достаточно публичных результатов.
2. Определи формат страницы. Для личного профиля нужен публичный `LOGIN/LOGIN` с корневым `README.md`. README проекта и GitHub Pages имеют другие адреса публикации; детали приведены в руководстве.
3. Зафиксируй охват чисел. Укажи владельцев, организации, архивы, ответвления, период и доступ токена. «Закрытый проект» может обозначать приватную видимость или завершённую работу. Эти признаки учитываются отдельно. Для обычного запроса следуй текущей реализации; дополнительные вопросы нужны, когда выбор меняет обещанный охват.
4. Перенеси шаблоны из `assets/` в целевой репозиторий по инструкции. Явно задай `GH_METRICS_USER` и проверь его соответствие владельцу токена. Сборщик рассчитан на пользовательский токен. Для GitHub App с токеном установки потребуется другой способ перечисления репозиториев.
5. Раздели два доступа. `GH_METRICS_TOKEN` читает разрешённые проекты; встроенный `GITHUB_TOKEN` записывает готовые файлы в репозиторий профиля. Получение прав приватного репозитория и разрешение публикации его сведений являются отдельными решениями. Публичный результат содержит только согласованные сводные показатели.
6. Сохрани существующее оформление или выбери подходящее пользователю. Карточку генерируй как самостоятельный SVG, данные как JSON. Подключай SVG обычным изображением в README. Для широких карточек проверь читаемость на телефоне.
7. Если требуется динамика во времени, выбери календарь GitHub, значения за фиксированные периоды или историю ежедневных снимков. Годовая сводка сама по себе показывает текущее окно. Для графика истории нужно отдельно сохранять временной ряд. Формат и порядок восстановления описаны в руководстве.
8. Проверь весь путь: запуск Actions, успешность сбора, источник коммитов, свежесть JSON, соответствие SVG, загрузку картинки через профиль GitHub и охват приватных проектов. Статус `success` проверяй вместе с `setup_needed` и `metric_sources`: исходный генератор возвращает код 0 даже при записи заглушки.
9. Запиши фактические проверки и границы охвата. При ошибке авторизации сохрани последний корректный опубликованный результат и сообщи о необходимом действии владельца. Выполни предусмотренные проектом commit, push и проверку публикации в пределах пользовательского запроса.

## Смысл показателей

- Список репозиториев берётся из `/user/repos` с `visibility=all`, всеми видами участия и обработкой страниц. Он относится к владельцу токена.
- В исходном генераторе архивы исключены из счётчиков репозиториев. Коммиты и запросы на слияние ищутся отдельными глобальными запросами и имеют собственную область поиска.
- `active_repositories` определяется по `pushed_at`; это активность репозитория любого участника.
- `commits` берётся из `/search/commits` по `author` и `author-date`, в пределах индексируемых основных веток и доступа токена. Запрос имеет нижнюю границу даты. Он отличается от числа в календаре вкладов.
- `restrictedContributionsCount` отражает вклады с ограниченной видимостью и публикуется отдельным показателем. Прибавление к коммитам создаёт повторный учёт.
- Языки отражают объём кода в выбранных репозиториях. В шаблоне выборка ограничена 25 активными репозиториями. Категории определяются эвристикой ключевых слов и могут пересекаться.
- Для строгого учёта всех веток, архивов или нескольких владельцев адаптируй сбор и методику. Заявление «всё учтено» подтверждай сверкой реального охвата.

## Проверка переноса

Проверь как минимум один ожидаемый приватный проект внутри доверенного процесса, получение второй страницы списка, защиту последнего успешного результата при ошибке, XML-структуру SVG и отсутствие названий приватных проектов в публикуемых файлах. Тестовые данные храни отдельно от публичных результатов.

Для русского текста применяй доступный `write-natural-russian`, затем вычитай весь материал. Дизайн и формулировки исходного профиля служат примером; персональные сведения автора шаблона заменяй данными нового владельца.
